# Motor controller firmware

Firmware for the STSPIN32G4 (STM32G431 + three-phase gate driver) on each motor controller board.
It is a CubeMX-generated HAL project built with CMake. Our own code lives in three folders next to it.

## Folder overview

```
motor_controller/
├── Core/                    CubeMX: init code, main.c
│   ├── Inc/                 generated peripheral headers
│   └── Src/                 generated init, ISRs, main
├── Drivers/                 ST HAL + CMSIS (vendor)
├── cmake/                   toolchain + CubeMX source list
├── control/                 pure C FOC core, no HAL
│   ├── include/control/     public core headers
│   └── src/                 FOC math, encoder, PLL, CAN codec
├── board/                   thin HAL wrappers per peripheral
│   ├── include/board/       driver interfaces app calls
│   └── src/                 LED now; SPI/ADC/PWM/CAN later
├── app/                     glue: scheduling, state machine
│   ├── include/app/         app_init / app_loop API
│   └── src/                 wires board ↔ control
├── CMakeLists.txt           builds firmware, links everything
└── motor_controller.ioc     CubeMX pins/clocks source of truth
```

- **`Core/`, `Drivers/`, `cmake/`** are generated by CubeMX from the `.ioc`. Only the `USER CODE` blocks in
  `main.c` are edited, and they just call `app_init()` and `app_loop()`. Regenerating keeps those edits.
- **`control/`** is the motor-control logic: Clarke/Park, SVPWM, PI loops, encoder decoding, the velocity PLL,
  the CAN frame codec and calibration. It is plain C with no hardware access. Its CMake target does not link
  the HAL, so a HAL `#include` fails to compile. That is what lets it be unit-tested on a computer.
- **`board/`** is the only code that touches the hardware. Each file is a thin wrapper around one peripheral.
- **`app/`** connects `board/` and `control/`. It holds the top-level state machine and decides what runs in
  the PWM interrupt and what runs in the main loop.

Dependencies only go one way: `app → board + control`, `board → HAL`, `control → nothing`.

## Building

Needs the Arm GNU toolchain (`arm-none-eabi-gcc`), CMake ≥ 3.22 and Ninja.

```sh
cmake --preset Debug
cmake --build build/Debug
```

The output is `build/Debug/motor_controller.elf`. `.clangd` reads `build/Debug/compile_commands.json`.

## Pin map

The pin-to-peripheral assignment comes from `motor_controller.ioc`. Net names come from the KiCad schematic
(`pcb/motor_board/`). Pins marked *internal* are bonded inside the STSPIN32G4 package between the MCU die and
the gate driver, so they never reach the PCB.

### External (on the PCB)

| Pin  | Peripheral / mode        | Net           | Purpose                                                         |
| ---- | ------------------------ | ------------- | --------------------------------------------------------------- |
| PA0  | ADC1_IN1                 | `VBUS_SENSE`  | Bus voltage through divider                                     |
| PC0  | ADC1_IN6                 | `MOTOR_TEMP`  | Motor thermistor (connector J3)                                 |
| PA4  | ADC2_IN17                | `MOSFET_TEMP` | Power stage thermistor TH1                                      |
| PA1  | OPAMP1_VINP              | `OPP1`        | Phase U shunt amp, + input                                      |
| PA3  | OPAMP1_VINM              | `OPN1`        | Phase U shunt amp, − input                                      |
| PA2  | OPAMP1_VOUT              | `OPO1`        | Phase U shunt amp output                                        |
| PA7  | OPAMP2_VINP              | `OPP2`        | Phase V shunt amp, + input                                      |
| PA5  | OPAMP2_VINM              | `OPN2`        | Phase V shunt amp, − input                                      |
| PA6  | OPAMP2_VOUT              | `OPO2`        | Phase V shunt amp output                                        |
| PB0  | OPAMP3_VINP              | `OPP3`        | Phase W shunt amp, + input                                      |
| PB2  | OPAMP3_VINM              | `OPN3`        | Phase W shunt amp, − input                                      |
| PB1  | OPAMP3_VOUT              | `OPO3`        | Phase W shunt amp output                                        |
| PA15 | GPIO out (pull-up, high) | `ENC_CS`      | AS5047P chip select (software NSS, idle high)                   |
| PB3  | SPI3_SCK                 | `ENC_SCK`     | AS5047P clock                                                   |
| PB4  | SPI3_MISO                | `ENC_MISO`    | AS5047P data out                                                |
| PB5  | SPI3_MOSI                | `ENC_MOSI`    | AS5047P data in                                                 |
| PA11 | FDCAN1_RX                | `CAN_RX`      | TCAN3414 RXD                                                    |
| PA12 | FDCAN1_TX                | `CAN_TX`      | TCAN3414 TXD                                                    |
| PD2  | GPIO out                 | `STATUS_LED`  | Status LED (heartbeat)                                          |
| PA13 | SWDIO                    | `SWDIO`       | Debug (J1)                                                      |
| PA14 | SWCLK                    | `SWCLK`       | Debug (J1)                                                      |
| PG10 | NRST                     | `NRST`        | Reset (J1)                                                      |
| PB8  | BOOT0                    | `BOOT0`       | Boot mode strap                                                 |
| PF0  | RCC_OSC_IN               | `OSC_IN`      | 25 MHz HSE crystal                                              |
| PF1  | RCC_OSC_OUT              | `OSC_OUT`     | 25 MHz HSE crystal                                              |
| PA10 | GPIO out (pull-down, low) | not connected | Held low so the UCPD dead-battery pull-down on PB4 stays off    |

Not connected on the board: PA8, PA9, PB6, PB7, PB9, PB10, PC1–PC5, PC13–PC15.

### Internal (MCU ↔ gate driver, inside the package)

| Pin  | Peripheral / mode | Driver signal | Purpose                                           |
| ---- | ----------------- | ------------- | ------------------------------------------------- |
| PE9  | TIM1_CH1          | INHU          | Phase U high-side PWM                             |
| PE8  | TIM1_CH1N         | INLU          | Phase U low-side PWM                              |
| PE11 | TIM1_CH2          | INHV          | Phase V high-side PWM                             |
| PE10 | TIM1_CH2N         | INLV          | Phase V low-side PWM                              |
| PE13 | TIM1_CH3          | INHW          | Phase W high-side PWM                             |
| PE12 | TIM1_CH3N         | INLW          | Phase W low-side PWM                              |
| PE15 | TIM1_BKIN         | nFAULT        | Driver fault → hardware PWM break                 |
| PE14 | GPIO in           | READY         | Driver ready flag                                 |
| PE7  | GPIO out (low)    | WAKE          | Driver wake / standby control                     |
| PC8  | I2C3_SCL          | SCL           | Driver configuration bus (address 0x47)           |
| PC9  | I2C3_SDA          | SDA           | Driver configuration bus                          |

The gate driver outputs (GHS1–3, GLS1–3, OUT1–3, BOOT1–3) and the power pins (VM, VCC, REGIN, SW, SCREF) are
pins of the driver, not of the MCU. See the `controller` sheet in the schematic.
