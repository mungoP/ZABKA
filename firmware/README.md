# Firmware

Embedded code for the robot's microcontrollers. Work in progress: the folders below are the planned layout.

| Folder              | Runs on                                   | Contents                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`motor_controller/`](motor_controller/) | STSPIN32G4 on each motor controller board | Field-oriented control (FOC) of the BLDC motor: three-shunt current loop, AS5047P encoder reading, MIT-style PD (impedance) control, CAN communication, gate-driver setup, fault handling and the 50 ms CAN-timeout damping. Bare-metal C on the STM32 HAL (CubeMX-generated), built with CMake. Split into `control/` (hardware-free control code that can be tested on a computer), `board/` (peripheral drivers) and `app/`. See its [README](motor_controller/README.md) for the folder layout and pin map. |
| `can_bridge_esp32/` | ESP32-C3                                  | CAN bridge between the Raspberry Pi and the motor boards, built with ESP-IDF: 200 Hz CAN cycle, IMU reading, e-stop latch, Pi watchdog and BMS polling.                                                                                                                                                                                                                                                                      |
| `common/`           | Both                                      | Shared CAN message definitions, so the motor boards and the bridge always agree on the frame format.                                                                                                                                                                                                                                                                                                                         |

See [`docs/system_architecture.md`](../docs/system_architecture.md) for how these fit together and [`docs/can_protocol.md`](../docs/can_protocol.md) for the bus format.
